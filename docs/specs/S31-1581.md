## 1. How the device does it

The firmware keeps the D81 as an open file on SD or USB. The FPGA's WD177x is not a floppy controller but a
mailbox:

- The 1581 CPU writes a command at `$6000-$7FFF` (four registers mirrored). BUSY goes up at the store, and the
  command goes into a 7-deep FIFO whose non-empty state is ITU high IRQ 1 (drive A) or 2 (drive B).
- The firmware reads the command and its completion bit (+0, +6), pops it (+6), and serves it (wd177x.cc):
  seek and step set GOTO_TRACK and the step time, and the stepper moves the head at 1 kHz; READ SECTOR reads the file
  into a DDR buffer and starts a DMA to the data register (mode 01), one byte per DRQ; WRITE SECTOR starts a DMA the
  other way (mode 10), and the last byte queues a completion entry; the firmware writes the file then; BUSY drops
  64 µs later.
- The 1581 DOS polls the status register; neither INTRQ nor DRQ reaches its CPU.

## 2. The model

`Wd177x` is that process in drive cycles (2 MHz): the four CPU registers, the firmware's sixteen, the FIFO, the DMA
state machine over guest DDR (`DmaMem`), the stepper and the index pulse (1 ms every 200 ms while the motor runs,
shown in type I status when the firmware enables it), and the head (`cur_track`, 0-83). The drive's reset
(`drv_reset`, not the power bit) holds it in its reset state.

## 3. In TRX64

Spec 875: `FdcController` fitted into a position's 1581 while it is off, in place of TRX64's WD1772. Register
reads and stores at the drive cycle, catch-up in drive cycles; `side0` and `motor_on` out; ready, disk change and
write protect in; `drive_reset` and `power` notifications. The bridge then:

- makes a position a 1581 when DRIVETYPE is 2: power off, `set_drive_type`, the controller fitted, the 1581 ROM
  (`set_rom` routes by board), power on;
- ready = motor and inserted, or force ready (`mm_drive.vhd:269` `rdy_n`); disk change and write protect from
  DISKCHANGE and SENSOR;
- serves the WD window at drive + 0x1800 from the model, SIDE from `side0`, TRACK from the head; drives ITU high IRQ
  1/2 from `irq()`; lends guest DDR for the DMA.

## 4. Checks

- Built: a command is BUSY at the store and reaches the firmware, a second one is dropped while busy but Force
  Interrupt is taken; a read sector by DMA; a write sector by DMA with its completion and the 64 µs delay; the
  stepper at step time; the index pulse.
- `scripts/smoke-1581.py`: the 1581 ROM installed from the menu; A as a 1581 lists a firmware-made D81
  (`0 "A SIDE" 3D`, `3160 BLOCKS FREE.`), saves and loads a program (the D81 file holds it afterwards); A and B both
  1581s at 8 and 9; A back to a 1541 with `drive.d64` beside B.
- The drive smoke (1541, NEW==TEST), the carts smoke, the Software IEC smoke.

## 5. Not in this spec

READ TRACK (the firmware does not implement it), the 1571, the 1581's drive sounds.
